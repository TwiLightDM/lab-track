## Как проверить
1. Переключиться на ветку с изменениями.
2. Установить зависимости и выполнить необходимые миграции БД (если применимо).
3. Запустить приложение.
4. Проверить основной сценарий работы изменённого функционала.
5. Проверить граничные случаи и корректность обработки ошибок.
6. Проверить, что существующий функционал продолжает работать.
7. Запустить тесты и убедиться, что они проходят.

## Чек-лист автора
- [ ] Изменение не больше ~400 строк (иначе разбить)
- [ ] Добавлены или обновлены тесты
- [ ] CI зелёный
- [ ] Обновлена документация (README, docs/), если нужно
- [ ] Сообщения коммитов по Conventional Commits (feat:, fix:, refactor:, test:, docs:, chore:)

## Чек-лист ревьюера
- [ ] Код понятен без пояснений автора
- [ ] Критерии приёмки задачи выполнены
- [ ] Нет очевидных проблем производительности (N+1, запросы в цикле)
- [ ] Обработка ошибок и граничных случаев
